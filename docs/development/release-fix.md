# 0.3.1 退出修正驗證（2026-10-31）

## 問題與修正

實際日誌為 `TerminalNeutralRejected`、`feedback=ProvenIncomplete`、`bridge=RetainedOperation`。原本冷退出只嘗試一次停止震動；可重試的原生 I/O 尚未排空便返回，導致實體註冊隔離，之後必須重新啟動。

現在在原本絕對退出期限內等待、精確取消／排空並重試同一個停止封包。立即輸入回呼仍不阻塞；不延長期限、不更換待完成封包或計數、不重試隔離／不確定的原生所有者。原生停止無法證明成功時仍保留錯誤，不假裝已釋放。

進階遊戲回饋若暫時無法退役，交由仍保有該 I/O 所有權的實體生命週期完成。僅該明確的暫時交接不算最終失敗；其他清理例外仍標記失敗，實體停止也必須成功。

## 離線證據

- 新回歸測試在修改前確實失敗：預期 `ExactNeutralAndQuiescent`，實際 `ProvenIncomplete`。
- 59 項 USB 回饋與冷退出檢查通過，包括精確封包重試、原本期限與隔離所有者不可重試。
- 99 項原生輸出、精確取消、bridge 與服務移除檢查通過。

## 實機證據與限制

- 使用者已在 v0.3.1 候選修正版的同一視窗手動完成「連接 → 斷開 → 切換輸出模式 → 再連接 → 斷開」，回覆「這次正常，沒有出現」釋放未完成。此確認只涵蓋這次操作，不代表長時間遊戲後退出或所有 USB 逾時已排除。

- 舊的 USB 輸出停滯狀態中，Windows 取消寫入成功（995 完成），但重新送出的停止指令持續逾時。增加重試不能解決這個狀態；本次重新插線後恢復。
- 重新插線後，同一個引擎連續 8 次連接／斷開，涵蓋 PS5、Xbox、Pro1、Pro2，全部成功；每次檢查清理成功且輸入／輸出就緒狀態已撤銷。
- 另一輪每次啟用短辨識震動並保持約 5 秒：前 6 次連接／斷開全部通過。第 7 次在建立輸入時遇到 `CommandTimedOut`，本輪沒有完成全部 8 次；已取消並完成退出，不將此輪記為全數通過。
- 這些是程式與 Windows 的觀測；本輪未要求使用者確認每次震動體感，不把「提交辨識脈衝」當作體感確認。
- 持續的硬體／Windows USB 輸出停滯、反覆初始化時的指令逾時及長時間遊戲後退出，仍不能宣稱完全排除。

## 手動重跑

先關閉其他 ControllerHub 實例，只保留目標手柄。這是會連接實體裝置及建立虛擬手柄的明確測試入口；不會啟用音訊、HidHide 或修改偏好設定。

```powershell
./dist/ControllerHub.exe --test-release-lifecycle ./lifecycle-result.txt
# 選用 --with-haptics：每次提交短辨識脈衝，保持約 5 秒再釋放。
# 選用 --bluetooth 或 --dualsense；這次的實機證據只涵蓋 Switch 2 USB。
```

總測試期限 120 秒，每次連接上限 15 秒；正常清理另保留其既有期限。掛起的原生驅動不能只靠管理程式期限保證退出，實機診斷應另以 `scripts/audio-probe-watchdog.ps1` 監控精確 PID／路徑／啟動時間。名稱為歷史沿用，此測試不會擷取或播放音訊。
